# CloudPulse Code of Conduct

## Our Community Values

CloudPulse is an open-source project built around collaboration, learning, respect, and constructive technical discussion.

Our community values:

- Respect for contributors regardless of experience level or background
- Constructive and professional communication
- Collaboration and knowledge sharing
- Patience with new open-source contributors
- Responsible technical discussion and disagreement
- Openness to different ideas and approaches
- A welcoming environment where people can participate without harassment

Everyone participating in CloudPulse is expected to help maintain a productive and inclusive community.

## Expected Behavior

Community members are expected to:

- communicate respectfully and professionally
- provide constructive feedback on code, documentation, issues, and pull requests
- respect different opinions, experiences, and technical approaches
- focus criticism on ideas and code rather than individuals
- welcome questions from new contributors
- accept constructive feedback gracefully
- give appropriate credit for the work and ideas of others
- respect contributor privacy
- follow project contribution and security guidelines
- help keep discussions relevant and productive

Technical disagreements are normal in open-source development. Contributors should discuss disagreements using evidence, reasoning, testing, and the needs of the project rather than personal attacks.

## Unacceptable Behavior

The following behavior is not acceptable in CloudPulse community spaces:

- harassment, intimidation, or discrimination
- insulting, degrading, or personally attacking another contributor
- discriminatory comments based on personal identity or background
- unwanted sexual attention or inappropriate sexual content
- threats of violence or encouragement of harmful behavior
- deliberately disrupting project discussions
- repeated trolling or inflammatory comments
- publishing another person's private information without permission
- intentionally submitting malicious code
- knowingly exposing credentials, secrets, or private information
- abusing issue trackers, pull requests, discussions, or other project communication channels

Disagreement with another contributor is not itself misconduct. The way disagreements are communicated must remain respectful and constructive.

## Scope

This Code of Conduct applies to all CloudPulse project spaces, including:

- GitHub issues
- pull requests and code reviews
- GitHub Discussions
- project documentation
- other communication conducted on behalf of CloudPulse

It also applies when an individual is officially representing the project in another public space.

## Reporting Violations

If you experience or observe behavior that violates this Code of Conduct, report it privately to the CloudPulse maintainer.

Reports should include, when possible:

- a description of what occurred
- where and when the incident occurred
- relevant links, screenshots, or other context
- whether the behavior is continuing
- any immediate safety or project concerns

Reports should not be posted publicly when doing so could expose private or sensitive information.

All reports will be reviewed as fairly and confidentially as reasonably possible.

## Enforcement Guidelines

Project maintainers are responsible for interpreting and enforcing this Code of Conduct.

Depending on the nature, severity, and history of a violation, maintainers may take actions including:

1. **Correction** — privately explaining why behavior was inappropriate and requesting a change.
2. **Warning** — issuing a formal warning and explaining the consequences of continued behavior.
3. **Temporary restriction** — temporarily limiting participation in project discussions, issues, or pull requests.
4. **Permanent restriction** — permanently removing a participant from project community spaces when serious or repeated violations make continued participation harmful to the community.

Serious threats, harassment, malicious activity, or security-related abuse may result in immediate stronger action.

Enforcement decisions should consider the available evidence, the impact on the community, previous behavior, and the need to maintain a safe and productive project environment.

## Maintainer Responsibilities

CloudPulse maintainers are expected to:

- apply these standards consistently
- review reports without unnecessary public disclosure
- avoid retaliation against people who report concerns in good faith
- remove or edit inappropriate contributions when necessary
- explain moderation decisions when doing so does not compromise privacy or safety
- prioritize the health of the project community

Maintainers who repeatedly violate the Code of Conduct should not use their project role to avoid accountability.

## Community Goal

CloudPulse should be a project where contributors can learn, propose ideas, improve software, and participate in open-source development without unnecessary hostility or intimidation.

The goal of this Code of Conduct is not to prevent disagreement. Its purpose is to ensure that disagreement and collaboration remain respectful, constructive, and focused on improving the project.
